agents2: what changed this week

4 to 10 October 2026. Six themes, explained with diagrams: how Pi handles long sessions, the agent team, skills reaching every runtime, separate home and work profiles, a more reliable toolchain, and Herdr theming.

agents2 is the private repo that builds Pi and the other agent tools on each Mac from one set of profiles. This week it moved from Pi works to Pi runs a team. Long sessions now summarise themselves cheaply and keep their memory. Named agent roles replace the built-in ones. Skills reach Cursor's cloud agents without being copied into every repo. Most of the remaining commits fixed things that had been silently failing.

1. Long sessions that remember

Compaction (summarising old conversation to free up space) now uses a cheap model. Memory is saved before anything is thrown away.

Compaction model

Each profile picks the model in pi.settings.compactionModel. Personal uses Haiku 5.5. The summary limit was raised so Haiku stops falling back to Opus.

OptMem

Long-term memory is installed and on in both profiles. A single-line memory survives sessions, compactions and model changes.

Follow-up suggestions

The profile now chooses the model that suggests your next message (followUpModel). Personal uses Haiku.

2. A team of named agents

Pi's built-in agents are off. Seven roles live in the repo, and each profile decides which model runs which role.

Roles: lead, coder, reviewer, oracle, researcher, scribe, qa. Workflows: saved plan and build scripts. An install script copies them, because Pi's workflow loader ignores symlinks. spawn-lead: a skill and command that creates a Herdr workspace with one lead agent in its own git worktree. The lead delegates the work.

3. Skills that reach every runtime

One catalog, many runtimes, including Cursor cloud agents, without copying skills into each repo.

New skills this week: tailnet-expose, article-explainer, work-inventory, spawn-lead and the latest frontend-design, plus usage guides for agent-browser. Fixed: the visual-artifact skill never loaded because it lives at skill/, not skills/.

4. Home and work, cleanly separated

Both profiles share one setup but differ where they must.

Personal

  • Claude Code models (Haiku for compaction and follow-ups)
  • Cursor cloud agents enabled
  • pi-topology-studio enabled
  • Shared mcp.json without work servers

Work

  • Six model aliases matching personal, via GitHub Copilot and Cursor
  • Work-only skills and MCP servers ported from v1
  • Its own mcp.work.json override
  • Cloudflare and context7 MCP servers dropped
